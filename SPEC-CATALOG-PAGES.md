# PackageHub — Главная страница и карточка пакета

Статус: утверждена владельцем 7 ноября 2026, решения в §9. Читатель страниц тот же, что у Updates: аналитик, владелец сервиса, понимание на уровне DevOps.

Числа сняты со стенда 7 ноября 2026: 848 пакетов, 41 273 версии, 100 141 зависимость. Интерфейс остаётся на английском.

## 1. Что не так сейчас

**Главная.** Это поиск, под которым идёт весь каталог по алфавиту. Страница не отвечает ни на один вопрос читателя: что у нас есть, свежие ли данные, что требует внимания, от чего мы зависим сильнее всего.

**Поиск.** Сортировка только по имени, поэтому точное совпадение теряется: `requests` стоит третьим после `http` и `libkcapi`, `core` — вторым. Запрос `pkg:pypi/django` не находит ничего, хотя на карточке показан именно purl.

**Карточка.** `PackagePage.jsx` — один компонент на 1220 строк, разделы идут один под другим. Что мешает:

- нет числа зависимых пакетов, хотя `used_by` уже считается для Updates;
- из 448 версий Django видно 10 плашек, у всех одинаковый `active`, линейки выпуска не различаются;
- дерево зависимостей занимает основную часть страницы, а сводки по нему нет;
- нельзя сравнить две версии;
- `Vulnerabilities: None` выглядит как результат проверки, хотя данных нет (#68);
- `Homepage: n/a` при том, что адрес у нас лежит (#69).

## 2. Что взяли у референсов

Открыто в браузере: deps.dev, crates.io, npmjs.com. Прочитано через субагентов как текст, без вёрстки: pkg.go.dev, lib.rs, pypi.org, nuget.org, hex.pm, rubygems.org, Snyk, libraries.io, ecosyste.ms, endoflife.date, OSV.dev, central.sonatype.com (частично). Не удалось посмотреть: Repology, Socket, mvnrepository, Artifact Hub, pkgs.org. О них в спеке нет утверждений.

| Механика | Где видели | Как делаем у нас |
|---|---|---|
| Строка фактов под заголовком, каждое значение ведёт в раздел | pkg.go.dev | версия, дата выпуска, лицензия, `used by`, зависимости, число версий |
| Счётчики на вкладках | hex.pm, crates.io, npm | `Dependencies 4`, `Used by 1`, `Versions 211` |

| Прямые и косвенные: два числа и полоса | deps.dev, lib.rs | для зависимостей и для `used by` |
| Таблица по умолчанию, граф по запросу | deps.dev | таблица плюс наше дерево с выбором окружения |
| Сравнение двух версий | deps.dev | показываем только изменения; deps.dev выводит и совпадающее |
| Версии, сгруппированные по линейкам | pkg.go.dev, endoflife.date | линейка, последний патч, дата; 1.10 у pydantic живёт рядом с 2.14 |
| Фильтры версий: пререлизы, отозванные, устаревшие | nuget.org | те же фильтры |
| Короткие списки на главной | hex.pm, crates.io | самые используемые, последние выпуски, на что посмотреть |
| Экосистемы со счётчиками как вход в каталог | libraries.io, OSV.dev | чипы над результатами |
| Команда установки и purl с кнопкой копирования | crates.io, nuget.org | одна команда на экосистему, без вкладок по инструментам |
| Честная область данных | Snyk, libraries.io | см. §3 |

Не берём:

- **Сводную оценку здоровья пакета.** У Snyk она складывается из активности репозитория, популярности и сообщества. Этих данных у нас нет, а SourceRank на libraries.io показывает, чем становится число без расшифровки.
- **README, звёзды, форки, OpenSSF Scorecard.** Для этого нужны новые внешние источники и другой масштаб работы.
- **Граф-паутину по умолчанию.** На `express` у deps.dev он нечитаем. Наше дерево с окружением (Python, ОС, target) полезнее, этого у deps.dev нет.
- **Вкладки установки под каждый инструмент** (восемь у NuGet). Читателю нужна координата, а не выбор инструмента.
- **Общие сообщения об ошибке.** deps.dev на `express` показывает баннер без объяснения причины.

## 3. Правила честности данных

Главное отличие от публичных сайтов: у нас каталог из 848 пакетов, а не весь реестр. Интерфейс обязан это говорить.

1. **`used by` считается в каталоге.** Подпись `in this catalog` обязательна. У Django здесь 0, на deps.dev 12 118. Ноль означает, что в каталоге нет зависимых, а не что пакет никому не нужен.
2. **Косвенные числа — нижняя граница.** Они считаются по последним версиям пакетов каталога. У последних версий 864 разных runtime-зависимости не разрешены в каталоге. Число пропущенных показываем: `+2 not in catalog`.
3. **Отсутствие проверки — не успех.** Различаем `No advisories found`, `Not checked for this version` и `Not collected for this ecosystem` (#68).
4. **Пустое поле называем.** Для Go лицензии и описания нет во всех 214 пакетах (решение §9 SPEC-UPDATES-DIGEST): показываем `Not published by the source`, а не `n/a`.
5. **Свежесть берём из прогонов.** `last_sync_at` в `/stats` меняется только при новых данных: у crates.io там 3 ноября, хотя прогон 6 ноября прошёл успешно. Главная берёт статус из `last_runs`.
6. **Факт вместо вывода.** Пишем `No release in 3+ years`, а не `abandoned`: `go-spew` не выпускался с 2018 года, потому что стабилен.
7. **Тестовые зависимости Go.** `go.mod` не отделяет их от runtime, поэтому `testify` на третьем месте среди самых используемых (45). Под списком стоит примечание.

## 4. Главная

Маршруты: `/` — главная, `/search?q=` — результаты. Сейчас обе роли у `/`.

Сверху вниз:

1. **Поиск.** Одно поле: имя или purl. purl сразу ведёт на карточку. Точное совпадение первым.
2. **Экосистемы.** Чипы со счётчиками: RPM 218, Go 214, crates.io 127, NuGet 90, PyPI 82, npm 76, Maven 41. Клик открывает `/search?ecosystem=`.
3. **Строка статуса.** `7 of 7 sources updated · last run 06.11, 10:03`. Сбой или устаревание видны здесь. Рядом: `Security advisories: PyPI only`.
4. **This week.** Один блок из Updates: `Needs attention` со строкой пакета и счётчики обновлений со ссылкой на `/updates?period=week`.
5. **Три списка по пять строк:**
   - `Most used in catalog`: `System.Runtime` 54, `golang.org/x/sys` 50;
   - `Latest releases`: версия, дата;
   - `Worth a look`: устаревшие, но используемые (`github.com/golang/protobuf` 5, `Microsoft.Rest.ClientRuntime` 3), затем ссылка `No release in 3+ years, used by 5+: 39 packages`.

Результаты поиска получают сортировку `Relevance` (по умолчанию), `Most used`, `Name`, фильтр по лицензии и `used by` в каждой строке.

## 5. Карточка пакета

### Шапка

Видна на всех вкладках:

- имя, тег экосистемы, выбор версии;
- описание;
- строка фактов: `Released 05.11.2026` · `MIT` · `Used by 1` · `Dependencies 4 + 2 optional` · `211 versions`;
- purl и команда установки с копированием, ссылки на репозиторий, домашнюю страницу, документацию;
- баннер, если применимо: `Deprecated` с текстом источника, `Yanked`, `Not the latest version` со ссылкой на последнюю.

Значение `latest` в адресе работает как псевдоним. deps.dev на `/express/latest` отвечает `Version Not Found`.

### Вкладки

| Вкладка | Содержимое |
|---|---|
| Overview | блоки Security, Licenses (своя и лицензии зависимостей), Dependencies, Used by, Release activity за 12 месяцев, Release lines; каждый ведёт в свой раздел |
| Dependencies | таблица: пакет, ограничение, разрешённая версия, тип, прямая или косвенная, лицензия; переключатель на дерево; окружение как сейчас |
| Used by | пакеты каталога, прямые и косвенные, с тем, какую версию они требуют |
| Versions | линейки выпуска, раскрытие до версий, фильтры; статус показывается, только если он не `active` |
| Compare | две версии, только различия |
| Sources | реестры и артефакты текущей версии |

Адрес: `/package/pypi/pydantic?version=2.14.3&tab=dependencies`. Версия и вкладка остаются в query: координаты Go содержат `/`, путь с сегментами был бы неоднозначным.

Линейка выпуска — плагинная логика: `major.minor` для PyPI, npm, crates, NuGet, Maven; `major` для Go; у RPM линеек нет, вкладка показывает плоский список. Контракт плагина менять не нужно: это функция слоя страницы на основе `versions_common`, если её хватит; иначе решение владельца по `base.py`.

### Compare

`pydantic 2.13.5 → 2.14.3`:

```
pydantic-core      ==2.46.5  → ==2.50.4
typing-extensions  >=4.14.1  → >=4.16.0
typing-inspection  >=0.4.2   → >=0.4.4
1 dependency unchanged
```

По умолчанию сравниваем с предыдущей стабильной. Строка в Updates получает ссылку `Compare` с `from` и `to`. Зависимости старых версий подгружаются при открытии: 71 % версий в состоянии `pending`, запрос к старой версии занял 0,6 с.

Лицензию версии сравнить нельзя: она хранится только на уровне пакета. Сравнение пишет `License per version is not stored`.

### Состояния

- `used by 0`: `No packages in this catalog depend on it`.
- Go без описания: строка описания скрыта, репозиторий выведен из пути модуля (U5).
- Вкладка с нулём зависимостей остаётся и говорит об этом.
- Неизвестная версия в адресе: сообщение и ссылка на последнюю.

## 6. API

| Что | Изменение |
|---|---|
| `GET /search` | параметр `sort=relevance` по умолчанию: точное имя, начало имени, остальное; `purl` в `q`; `used_by` в ответе |
| `GET /packages`, `GET /search` | сортировка `used_by`, фильтры `min_used_by`, `deprecated`, `released_before`, поле `used_by` в строке |
| Новый `GET {coords}/overview?version=` | счётчики версий, прямых и косвенных зависимостей и зависимых, не разрешённые в каталоге, лицензии, активность, линейки |
| Новый `GET /catalog/summary` | счётчики экосистем и лицензий, списки главной |
| Новый `GET {coords}/dependents` | список с курсором, `relation`, `constraint` |
| Новый `GET {coords}/versions/compare?from=&to=` | различия зависимостей, статуса, дат |
| `GET {coords}/versions` | `line`, фильтр `line` |

Графовые запросы считаем на лету: все рёбра последних версий строятся за 13 мс, транзитивное замыкание всех пакетов — за 0,4 с. Кеш или таблица нужны только при росте каталога. Индекса на `dependencies.resolved_package_id` нет: фильтр по нему — последовательное чтение, 26 мс на 100 тысяч строк, `overview` отвечает за 45–95 мс. При росте каталога индекс добавляется первым. Миграции не требуются, кроме заполнения #69.

## 7. Этапы

Каждый этап — отдельный PR, задача для исполнителя, проверка мной.

| Этап | Что | Зависит от |
|---|---|---|
| UX0 | правила §3 в текущем интерфейсе, #68, #69, релевантность и purl в поиске, псевдоним `latest` | — |
| UX1 | карточка: разбиение компонента, шапка, строка фактов, вкладки, Overview; `counts` | UX0 |
| UX2 | главная и `/search` | UX0 |
| UX3 | вкладка Used by, эндпоинт `dependents` | UX1 |
| UX4 | вкладка Versions: линейки, фильтры, активность | UX1 |
| UX5 | вкладка Dependencies: таблица и сводка, дерево как второй вид | UX1 |
| UX6 | Compare, ссылка из Updates | UX1, UX5 |

UX2 и UX1 не зависят друг от друга. Этапы U3–U5 дайджеста можно вести параллельно: общая точка только у U5 (репозиторий Go) и UX1 (ссылки в шапке).

## 8. Вне рамок

- Источник уязвимостей (OSV и т. п.): отдельный проект, §9.
- Сервисы и проекты как потребители пакетов: у нас нет этих данных.
- README и метрики репозитория.
- Лицензия на уровне версии.
- Семейства в каталоге: сначала U3 на Updates.

## 9. Решения владельца

1. **Уязвимости.** Показываем честное `not collected`. Подключение источника (OSV) — отдельный этап со своей спекой.
2. **Порог давности.** `No release in 3+ years` при `used by ≥ 5`.
3. **Порядок этапов.** UX0, UX1, UX2, затем UX3–UX6, всё в одном PR.
