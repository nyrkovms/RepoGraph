# PackageHub — Главная страница и карточка пакета

Статус: утверждена владельцем 7 ноября 2026, решения в §9. Читатель страниц тот же, что у Updates: аналитик, владелец сервиса, понимание на уровне DevOps.

Числа сняты со стенда 7 ноября 2026: 848 пакетов, 41 273 версии, 100 141 зависимость. Интерфейс остаётся на английском.

## 1. Что не так сейчас

Раздел описывает состояние до UX0–UX6; всё перечисленное исправлено (§7).

**Главная.** Это поиск, под которым идёт весь каталог по алфавиту. Страница не отвечает ни на один вопрос читателя: что у нас есть, свежие ли данные, что требует внимания, от чего мы зависим сильнее всего.

**Поиск.** Сортировка только по имени, поэтому точное совпадение теряется: `requests` стоит третьим после `http` и `libkcapi`, `core` — вторым. Запрос `pkg:pypi/django` не находит ничего, хотя на карточке показан именно purl.

**Карточка.** `PackagePage.jsx` — был один компонент на 1220 строк, разделы идут один под другим. Что мешало:

- нет числа зависимых пакетов, хотя `used_by` уже считается для Updates;
- из 448 версий Django видно 10 плашек, у всех одинаковый `active`, линейки выпуска не различаются;
- дерево зависимостей занимает основную часть страницы, а сводки по нему нет;
- нельзя сравнить две версии;
- `Vulnerabilities: None` выглядит как результат проверки, хотя данных нет (#68, закрыт);
- `Homepage: n/a` при том, что адрес у нас лежал (#69, закрыт).

## 2. Что взяли у референсов

Открыто в браузере: deps.dev, crates.io, npmjs.com. Прочитано через субагентов как текст, без вёрстки: pkg.go.dev, lib.rs, pypi.org, nuget.org, hex.pm, rubygems.org, Snyk, libraries.io, ecosyste.ms, endoflife.date, OSV.dev, central.sonatype.com (частично). Не удалось посмотреть: Repology, Socket, mvnrepository, Artifact Hub, pkgs.org. О них в спеке нет утверждений.

| Экосистемы со счётчиками как вход в каталог | libraries.io, OSV.dev | чипы над результатами |
| Команда установки и purl с кнопкой копирования | crates.io, nuget.org | одна команда на экосистему, без вкладок по инструментам |
| Честная область данных | Snyk, libraries.io | см. §3 |

Не берём:

- **Сводную оценку здоровья пакета.** У Snyk она складывается из активности репозитория, популярности и сообщества. Этих данных у нас нет, а SourceRank на libraries.io показывает, чем становится число без расшифровки.
- **README, звёзды, форки, OpenSSF Scorecard.** Для этого нужны новые внешние источники и другой масштаб работы.
- **Граф-паутину по умолчанию.** На `express` у deps.dev он нечитаем. Наше дерево с окружением (Python, ОС, target) полезнее, этого у deps.dev нет.
- **Вкладки установки под каждый инструмент** (восемь у NuGet). Читателю нужна координата, а не выбор инструмента.
- **Общие сообщения об ошибке.** deps.dev на `express` показывает баннер без объяснения причины.

## 3. Правила честности данных

Главное отличие от публичных сайтов: у нас каталог из 848 пакетов, а не весь реестр. Интерфейс обязан это говорить.

1. **`used by` считается в каталоге.** Подпись `in this catalog` обязательна. У Django здесь 0, на deps.dev 12 118. Ноль означает, что в каталоге нет зависимых, а не что пакет никому не нужен.
2. **Косвенные числа — нижняя граница.** Они считаются по последним версиям пакетов каталога. У последних версий 864 разных runtime-зависимости не разрешены в каталоге. Число пропущенных показываем: `+2 not in catalog`.
3. **Отсутствие проверки — не успех.** Различаем `No advisories found`, `Not checked for this version` и `Not collected for this ecosystem` (#68, закрыт).
4. **Пустое поле называем.** Для Go лицензии и описания нет во всех 214 пакетах (решение §9 SPEC-UPDATES-DIGEST): показываем `Not published by the source`, а не `n/a`.
5. **Свежесть берём из прогонов.** `last_sync_at` в `/stats` меняется только при новых данных: у crates.io там 3 ноября, хотя прогон 6 ноября прошёл успешно. Главная берёт статус из `last_runs`.
6. **Факт вместо вывода.** Пишем `No release in 3+ years`, а не `abandoned`: `go-spew` не выпускался с 2018 года, потому что стабилен.
7. **Тестовые зависимости Go.** `go.mod` не отделяет их от runtime, поэтому `testify` на третьем месте среди самых используемых (45). Под списком стоит примечание.
8. **RPM считается только по прямым рёбрам.** Дерево находит пакет capability через поставщика, а граф каталога видит только `resolved_package_id`. Поэтому для RPM косвенные числа, `not_in_catalog` и лицензии зависимостей не показываются, а `used by` подписан `Dependencies on capabilities are not counted`. Хранение поставщиков — решение владельца (§9).

## 4. Главная

Маршруты: `/` — главная, `/search?q=` — результаты. Закладка старого вида `/?q=…` переходит на `/search` с тем же запросом; один `ecosystem` остаётся фильтром главной.

Правило страницы: строка без объяснения не показывается. Читатель должен понять, что это, почему это здесь и что делать дальше.

Сверху вниз:

1. **Поиск.** Одно поле: имя или purl. purl сразу ведёт на карточку. Enter открывает выдачу: подсказка выбирается только стрелками или кликом, заранее ничего не подсвечено.
2. **Экосистемы.** Чипы со счётчиками работают на месте: `/?ecosystem=go` сужает поиск и все блоки ниже и никуда не уводит. Под выбранным чипом ссылка `Browse all 214 Go packages` ведёт в `/search?ecosystem=go`.
3. **Строка статуса.** `7 of 7 sources updated · last run 06.11, 10:03`. Сбой или устаревание видны здесь. Рядом: `Security advisories: PyPI only`.
4. **This week.** Период совпадает со страницей Updates: она теперь открывается на неделе, `day` остаётся в переключателе.
   - `Needs attention`. Каждая строка объясняет себя: причина по флагу и два действия. `New major version: expect breaking changes.`, `Compare 3.0.0 → 4.0.0`, `Who uses it (1)`. Без зависимых: `Nothing in this catalog depends on it`. Тот же текст на странице Updates.
   - `Updated, most used first`: пять обновлённых пакетов без флагов и не только с пререлизами: название, версии, тип обновления, описание, `used by N`. Здесь важен порядок по важности, поэтому отдельного списка последних выпусков нет.
5. **Два списка:**
   - `Most used in catalog`, подзаголовок `Packages the rest of the catalog depends on`: название, экосистема, описание или последняя версия, `54 dependents`;
   - `Worth a look`: подзаголовок `Deprecated, but other packages still use them`, строки с `used by N`; затем `39 packages had no release in 3+ years and are used by 5 or more` ссылкой на список.

Результаты поиска получают сортировку `Relevance` (по умолчанию), `Most used`, `Name`, фильтр по лицензии и `used by` в каждой строке.

## 5. Карточка пакета

### Компоновка

Сверху имя, тег экосистемы, выбор версии, описание и баннеры. Ниже две колонки: слева вкладки и содержимое, справа узкая панель с фактами. Подсчёты живут на вкладках и в обзоре, панель отвечает на вопрос «что это и как его взять». Под 760 px панель уходит под шапку.

Панель, значения друг под другом: `Released`, `License`, `Repository`, `Homepage`, `Documentation`, координаты Maven или RPM, затем `Install` и `purl` с копированием. `License`: `Not published by the source`, если пусто. Пустые строки скрыты.

Баннеры, если применимо: `Deprecated` с текстом источника, `Yanked`, `Not the latest version` со ссылкой на последнюю.

Значение `latest` в адресе работает как псевдоним. deps.dev на `/express/latest` отвечает `Version Not Found`.

### Вкладки

| Вкладка | Содержимое |
|---|---|
| Overview | сначала одно предложение-сводка, затем разделы без рамок: Security, Dependencies и Used by рядом, Licenses, Release activity за 12 месяцев, Release lines; у раздела со своей вкладкой ссылка `View all` |
| Dependencies | таблица: пакет, ограничение, разрешённая версия, тип, прямая или косвенная, лицензия, путь для косвенных; переключатель на дерево; окружение как сейчас; счётчик на вкладке — прямые |
| Used by | пакеты каталога, прямые и косвенные, с тем, какую версию они требуют; счётчик на вкладке — прямые, как в шапке |
| Versions | линейки выпуска, раскрытие до версий, виды `Prereleases`, `Not active`, `Deprecated`, `All`; статус показывается, только если он не `active` |
| Compare | две версии, только различия |
| Sources | реестры и артефакты текущей версии |

Адрес: `/package/pypi/pydantic?version=2.14.3&tab=dependencies`. Значения `tab`: `overview` (по умолчанию, в том числе для неизвестного значения), `dependencies`, `used-by`, `versions`, `compare`, `sources`. Версия, вкладка и фильтры вкладок (`deps`, `dep_relation`, `relation`, `view`, `line`, `from`) остаются в query: координаты Go содержат `/`, путь с сегментами был бы неоднозначным.

Линейка выпуска — плагинная логика: `major.minor` для PyPI, npm, crates, NuGet, Maven; `major` для Go; у RPM линеек нет, вкладка показывает плоский список. Контракт плагина не менялся: это чистая функция `app/services/release_lines.py`.

### Compare

`pydantic 2.13.5 → 2.14.3`:

```
pydantic-core      ==2.46.5  → ==2.50.4
typing-extensions  >=4.14.1  → >=4.16.0
typing-inspection  >=0.4.2   → >=0.4.4
1 dependency unchanged
```

По умолчанию сравниваем с предыдущей стабильной. Строка в Updates получает ссылку `Compare` с `from` и `to`. Зависимости старых версий подгружаются при открытии: 71 % версий в состоянии `pending`, запрос к старой версии занял 0,6 с.

`from` по умолчанию — ближайшая младшая стабильная активная версия. Лицензию версии сравнить нельзя: она хранится только на уровне пакета. Сравнение пишет `License per version is not stored`.

### Состояния

- `used by 0`: `No packages in this catalog depend on it`.
- Go без описания: строка описания скрыта, репозиторий из пути модуля пока не выводится: это U5 дайджеста, не сделано.
- Вкладка с нулём зависимостей остаётся и говорит об этом.
- Неизвестная версия в адресе: сообщение и ссылка на последнюю; факты, идентификаторы и вкладки скрыты.
- Пустой фильтр в Used by говорит о фильтре, а не о том, что пакет никому не нужен.

## 6. API

| Что | Изменение |
|---|---|
| `GET /search` | параметр `sort=relevance` по умолчанию: точное имя, начало имени, остальное; `purl` в `q`; `used_by` в ответе |
| `GET /packages`, `GET /search` | сортировка `used_by`, фильтры `min_used_by`, `deprecated`, `released_before`, поле `used_by` в строке |
| Новый `GET {coords}/overview?version=` | счётчики версий, прямых и косвенных зависимостей и зависимых, не разрешённые в каталоге, лицензии, активность, линейки |
| Новый `GET /catalog/summary?ecosystem=` | счётчики экосистем и лицензий, списки главной; `ecosystem` сужает всё, кроме счётчиков экосистем |
| Новый `GET {coords}/dependents` | список с курсором, `relation`, `requires` |
| Новый `GET {coords}/versions/compare?from=&to=` | различия зависимостей, статуса, дат |
| `GET {coords}/versions` | поля `line`, `is_prerelease`; фильтры `line`, `prerelease`, `not_active`, `deprecated` |
| `GET {coords}/versions/{version}` | фактический статус вместо хранимого, `line` |
| Узел дерева зависимостей | поле `license` |

Графовые запросы считаем на лету: все рёбра последних версий строятся за 13 мс, транзитивное замыкание всех пакетов — за 0,4 с. Кеш или таблица нужны только при росте каталога. Индекса на `dependencies.resolved_package_id` нет: фильтр по нему — последовательное чтение, 26 мс на 100 тысяч строк, `overview` отвечает за 45–95 мс. При росте каталога индекс добавляется первым. Миграции не требуются, кроме заполнения #69: она сделана миграцией `20261107_0015`.

## 8. Вне рамок

- Источник уязвимостей (OSV и т. п.): отдельный проект, §9.
- Сервисы и проекты как потребители пакетов: у нас нет этих данных.
- README и метрики репозитория.
- Лицензия на уровне версии.
- Семейства в каталоге: сначала U3 на Updates.

## 9. Решения владельца

1. **Уязвимости.** Показываем честное `not collected`. Подключение источника (OSV) — отдельный этап со своей спекой.
2. **Порог давности.** `No release in 3+ years` при `used by ≥ 5`.
3. **Порядок этапов.** UX0, UX1, UX2, затем UX3–UX6, всё в одном PR. Выполнено (PR #70).
4. **Открыто: поставщики RPM.** Хранить ли пакет-поставщик capability в графе. Без этого §3 правило 8 остаётся в силе.
