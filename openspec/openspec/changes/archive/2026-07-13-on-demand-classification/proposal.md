# Proposal: Классификация по требованию (сервис фактов)

## Why

Классификатор станет частью системы проверок прокси-репозитория: проверка спрашивает «дай факты о пакете X» и получает ответ синхронно, независимо от того, был ли пакет в каталоге. Сейчас факты появляются только асинхронно (sync → probe → classify через Celery) — внешней проверке не на что опереться. Позиционирование фиксируется: **решение выдаёт только факты** (роли, свойства, статусы, evidence); вердикты допуска/блокировки — за пределами решения, их принимает потребитель.

## What Changes

- Новый эндпоинт `GET /api/v1/facts/{ecosystem}/{name}` — единая точка для системы проверок: гарантирует наличие фактов по **latest-версии** (lazy fetch пакета → probe → классификация выполняются синхронно inline, если отсутствуют) и возвращает их одним ответом. Fail-fast при недоступности upstream (без partial), общий таймаут запроса настраивается.
- Параметр `refresh=true` — принудительная пересинхронизация метаданных перед выдачей (свежий deprecated/yanked/latest).
- Требование «только факты»: ответ MUST NOT содержать полей решения (allow/deny/score) — контракт фиксируется спекой.
- Политика охвата фиксируется требованием: автоматическая классификация — **только latest** каждого пакета. Пер-версионная классификация, ре-классификация по событиям жизненного цикла и привязка блока классификации к селектору версий в UI — **сознательно не решены**: блок помечается в документации как требующий проработки (Open Questions + README).

## Capabilities

### Modified Capabilities

- `classification`: добавляются требования сервиса фактов по требованию, latest-политики и запрета вердиктов в ответе.

## Impact

- Код: `api/v1/facts.py` (+схема ответа), синхронная оркестрация ensure fetch→probe→classify (переиспользование существующих корутин), настройка таймаута; README (позиционирование + открытый блок).
- Не затрагивается: правила классификатора, фоновые контуры, UI.
