# classification: факты по конкретной версии

## ADDED Requirements

### Requirement: Факты по требованию для конкретной версии
Сервис фактов SHALL принимать версию пакета и синхронно возвращать факты именно этой версии, достраивая недостающее в рамках запроса: fetch версии, probe версии, классификацию версии. Если версия отсутствует в каталоге, но существует в upstream, она SHALL быть загружена (метаданные версии + артефакты) и классифицирована в том же вызове. Отсутствие версии в upstream SHALL приводить к 404 без частичного ответа.

#### Scenario: Версия отсутствует в каталоге
- **WHEN** система проверок запрашивает факты о версии пакета, которой нет в каталоге, но которая опубликована в реестре
- **THEN** в одном вызове загружаются метаданные версии, выполняются probe и классификация, ответ содержит факты именно этой версии

#### Scenario: Несуществующая версия
- **WHEN** запрошена версия, которой нет в upstream
- **THEN** ответ 404 без частичных фактов

#### Scenario: Не-latest версия не смещает latest
- **WHEN** классифицируется версия, отличная от latest
- **THEN** вердикт привязан к этой версии, классификация latest остаётся неизменной

### Requirement: Версионная корректность манифеста классификатора
Классификатор SHALL получать манифест именно классифицируемой версии. Для pypi манифест ({info, urls}) SHALL браться из данных этой версии, а не из метаданных пакета (соответствующих latest). Классификация версии, отличной от latest, MUST NOT использовать классификаторы/зависимости/summary другой версии.

#### Scenario: Классификация исторической pypi-версии
- **WHEN** классифицируется не-latest pypi-версия, у которой набор classifiers отличается от latest
- **THEN** вердикт опирается на classifiers этой версии

#### Scenario: Регрессия latest
- **WHEN** после изменения источника манифеста классифицируется latest-версия
- **THEN** вердикт совпадает с вердиктом до изменения (эталоны не смещаются)
