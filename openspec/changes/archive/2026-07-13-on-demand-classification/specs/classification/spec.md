# classification: сервис фактов по требованию

## ADDED Requirements

### Requirement: Факты по требованию
`GET /api/v1/facts/{ecosystem}/{name}` SHALL синхронно возвращать факты о latest-версии пакета, выполняя недостающие шаги в рамках запроса: lazy fetch пакета, probe latest-версии, классификацию. Повторный вызов при уже готовых данных SHALL отвечать из каталога без сетевых обращений к реестру. Параметр `refresh=true` SHALL пересинхронизировать метаданные пакета перед выдачей. Весь вызов SHALL ограничиваться настраиваемым таймаутом (превышение — 504).

#### Scenario: Пакет не в каталоге
- **WHEN** система проверок запрашивает факты о пакете, которого нет в каталоге
- **THEN** в одном вызове выполняются fetch, probe и классификация, ответ содержит факты latest-версии

#### Scenario: Повторный запрос
- **WHEN** факты уже собраны и запрошены повторно без refresh
- **THEN** ответ отдаётся из каталога без обращений к upstream

#### Scenario: Пакет признан deprecated после классификации
- **WHEN** вызов с refresh=true для пакета, помеченного deprecated в реестре после последнего sync
- **THEN** ответ содержит актуальный признак deprecated из живых данных каталога

### Requirement: Fail-fast сервиса фактов
Сервис фактов SHALL завершаться явной ошибкой без частичного ответа: 404 при отсутствии пакета в upstream, 502 при отказе авторизации реестра, 503 при транзиентной недоступности upstream. Permanent-результат probe («нет пригодного дистрибутива», битый архив) MUST NOT считаться ошибкой: классификация выполняется по правилам probe-недоступности, ответ 200.

#### Scenario: Upstream недоступен
- **WHEN** реестр не отвечает при холодном запросе фактов
- **THEN** ответ 503 с причиной, без частичных фактов

#### Scenario: У пакета нет wheel
- **WHEN** запрошены факты pypi-пакета без опубликованного wheel
- **THEN** ответ 200 со свойством sdist-only и статусом классификации по правилам недоступного probe

### Requirement: Только факты, без вердиктов
Ответ сервиса фактов SHALL содержать только факты: идентичность пакета, жизненный цикл (deprecated, статус версии) из живых данных каталога, классификацию (статус, роли с evidence, машинные и эффективные свойства, пометки кураторов, связи), реестры присутствия с флагами коллизий, метки времени и версию правил. Ответ MUST NOT содержать полей решения о допуске (allow/deny/decision/score) — решения принимает вызывающая система проверок.

#### Scenario: Контракт ответа
- **WHEN** запрошены факты любого пакета
- **THEN** ответ содержит facets/capabilities/status и не содержит полей allow, deny, decision, score

### Requirement: Политика охвата — latest
Автоматическая классификация (после probe) и сервис фактов SHALL работать по версии dist-tag `latest` пакета. Классификация иных версий SHALL выполняться только по явному административному запросу. Режимы обновления вердиктов (ре-классификация по событиям жизненного цикла, пер-версионная классификация, привязка отображения к выбору версии) — вне данного контракта и зафиксированы как требующие проработки.

#### Scenario: Смена latest при refresh
- **WHEN** refresh=true обнаруживает, что dist-tag latest сместился на новую версию
- **THEN** факты в ответе относятся к новой latest-версии
