# fetch-probe: probe дистрибутива

## ADDED Requirements

### Requirement: Probe как отдельный контур
Probe (скачивание дистрибутива и извлечение офлайн-фактов) SHALL выполняться отдельной фоновой задачей со своей очередью и своим лимитом параллелизма. Сбой или отставание probe MUST NOT блокировать или откатывать sync метаданных.

#### Scenario: Ошибка probe не влияет на каталог
- **WHEN** sync пакета прошёл успешно, а probe его latest-версии завершился ошибкой скачивания
- **THEN** метаданные пакета доступны в каталоге, а ошибка probe зафиксирована независимо

### Requirement: Автоматический probe представительного дистрибутива latest-версии
После успешного sync пакета фетчер SHALL ставить probe-задачу для версии, на которую указывает dist-tag `latest`, если у этой версии ещё нет представительного результата probe. У версии может быть несколько дистрибутивов (sdist + wheels под платформы); автоматически пробится один представительный (правило выбора — см. требование выбора артефакта), его результат SHALL помечаться `is_representative`. Probe произвольной версии или конкретного дистрибутива SHALL выполняться по явному запросу (админ-API или внутренний потребитель) и сохраняться дополнительной строкой.

#### Scenario: Смена latest
- **WHEN** при refresh пакета dist-tag `latest` сместился на новую версию
- **THEN** ставится probe-задача для новой версии, результат probe прежней версии сохраняется

#### Scenario: Явный probe платформенного wheel
- **WHEN** у версии уже есть представительный результат (`none-any` wheel) и запрошен probe конкретного `manylinux`-wheel
- **THEN** появляется вторая строка результата для этого дистрибутива, представительная строка не меняется

### Requirement: Идемпотентность и неизменяемость результата probe
Результат probe SHALL храниться по одной строке на пару (версия, имя дистрибутива) с привязкой к версии (не к строке артефакта) и с фиксацией реестра происхождения. Существующая строка MUST NOT перезаписываться повторным probe той же пары; повторное выполнение допускается только после явного административного удаления результата.

#### Scenario: Повторная постановка probe-задачи
- **WHEN** probe-задача поставлена для дистрибутива, у которого результат уже есть
- **THEN** задача завершается без сетевых запросов и без изменения существующей строки

#### Scenario: Артефакты пересозданы при refresh
- **WHEN** batch refresh пересоздал строки артефактов версии
- **THEN** результаты probe этой версии остаются доступными и неизменными

### Requirement: Выбор артефакта для probe (PyPI)
Для PyPI фетчер SHALL выбирать один wheel: только `bdist_wheel` с размером не более настраиваемого лимита (default 20 МБ); при наличии нескольких — предпочтение кроссплатформенному (`none-any`). Имя выбранного артефакта и реестр его происхождения SHALL фиксироваться в результате; артефакт скачивается из того реестра, которому принадлежит (версии, существующие только в одном реестре, пробятся из него). Отсутствие пригодного wheel SHALL фиксироваться как permanent-результат с причиной (`no wheel available` / `all wheels exceed size limit`); sdist в этом случае не скачивается.

#### Scenario: Есть платформенные и кроссплатформенный wheel
- **WHEN** у версии есть wheels `cp312-manylinux` и `py3-none-any`, оба в пределах лимита
- **THEN** для probe выбирается `py3-none-any`, и в фактах отражено `platform_wheel = false`

#### Scenario: Только огромные wheels
- **WHEN** все wheels версии превышают лимит размера
- **THEN** сохраняется результат с ошибкой `all wheels exceed size limit`, скачивание не выполняется

### Requirement: Извлекаемые факты
Из дистрибутива probe SHALL извлекать: сырой текст `entry_points.txt` и `top_level.txt` (без парсинга), факты о составе файлов (общее число, счётчики расширений top-15, скрипты из `.data/scripts/`, признак платформенного wheel), README (лимит 500 000 символов). README SHALL сохраняться в слой описаний с origin `tarball-readme`; парсинг и интерпретация фактов остаются за потребителем (классификатором).

#### Scenario: Wheel с entry_points
- **WHEN** probe распаковывает wheel, содержащий `*.dist-info/entry_points.txt`
- **THEN** содержимое файла сохраняется в результате probe дословно

### Requirement: Безопасная распаковка
Probe SHALL распаковывать архив только в памяти, читать только известные целевые файлы по именам и MUST NOT выполнять полную распаковку архива (`extractall`) или запись содержимого на диск. Размер архива SHALL проверяться до скачивания (по метаданным) и ограничиваться при чтении.

#### Scenario: Повреждённый архив
- **WHEN** скачанный файл не является корректным zip/tar
- **THEN** сохраняется permanent-результат с ошибкой парсинга, задача не ретраится
