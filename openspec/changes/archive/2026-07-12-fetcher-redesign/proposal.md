# Proposal: Единый фетчер объединённого решения (PackageHub + classifire)

## Why

Сейчас существуют два независимых фетчера с зеркальными компромиссами: classifire качает глубоко (манифест + дистрибутив + probe-факты), но только одну версию пакета и без production-контура; PackageHub (repograph) качает широко (все версии, зависимости, артефакты, уязвимости) с retry/очередями/метриками, но не заглядывает внутрь дистрибутива и не умеет авторизацию к реестру. Объединённому решению — веб-интерфейсу к прокси-репозиторию — нужны обе оси: классификатору нужен probe, каталогу и резолверу нужны все версии. Дублирование двух фетчеров закрепляет расхождение моделей данных.

Ориентиры класса продукта — socket.dev и deps.dev (граф знаний обо всех артефактах + поиск); наш дифференциатор — слой классификации ролей/свойств, которого у аналогов нет. Классификация при этом не часть фетчера: фетчер собирает факты (метаданные + probe), классификатор — отдельный потребитель, и его отсутствие для экосистемы не блокирует каталог.

## What Changes

- Проектируется единый фетчер на каркасе PackageHub (asyncio + httpx + Celery, PostgreSQL) с шестью контурами синхронизации: seed, lazy fetch, batch refresh, retry — и новыми контурами **probe** (скачивание и распаковка дистрибутива) и **enumeration** (полная индексация реестров, поддерживающих листинг: внутренние Nexus/Verdaccio, PyTorch index).
- Все контуры работают **per-registry**, не per-ecosystem: у одной экосистемы может быть несколько реестров (pypi.org + PyTorch index + внутренние hosted/proxy npm и PyPI). Реестр добавляется строкой через admin API без деплоя; расписание, курсор и состояние sync — свои у каждого реестра.
- Протокол коннектора отделяется от экосистемы (`registry.protocol`): в этом чейндже — `pypi-json` (pypi.org), `pypi-simple` (PEP 503/691 — PyTorch index, внутренние hosted), `npm` (npmjs.org, Verdaccio, Nexus npm — один протокол); контракт рассчитан на будущие `maven2`, `goproxy` и `go-git` (внутренние Go-модули живут в git, не в Nexus). Из Nexus подключаются только hosted-репозитории (group и proxy не регистрируются). Пакет остаётся один на `(ecosystem, namespace, normalized_name)`; версии — объединение по реестрам, артефакты помнят свой реестр; коллизии имён между внутренними и публичными реестрами фиксируются как сигнал (dependency confusion).
- Probe переносится из classifire как отдельная стадия с собственным профилем нагрузки: immutable-результат на дистрибутив (у версии их может быть несколько — wheels под платформы, sdist; ключ `version + artifact_filename`), по умолчанию пробится один представительный дистрибутив, лимиты размеров, эвристика выбора wheel, error как полноценный результат.
- Конфигурация реестров становится данными, а не env/INI: адрес, auth (Bearer/Basic), прокси-URL живут в таблице `registry` (`auth_config`); правило `headers_for` из classifire (токен не отправляется на CDN при редиректе) — обязательный инвариант.
- Retry-таксономия PackageHub (retryable/permanent, backoff + jitter, `sync_failures`) распространяется на probe; добавляется permanent-класс «artifact unusable» (bad archive, превышение лимита, нет пригодного артефакта).
- Транспорт: один httpx-клиент на процесс с connection pool (вместо клиента на запрос), семафор параллелизма probe, реальное применение rate limit коннектора.
- Экономия хранения: `releases` PyPI не сохраняется в `raw_metadata` пакета (правило classifire); полный ответ раскладывается по версиям.
- npm-коннектор закладывается в контракт фетчера сразу (versioned endpoint + npm-probe из classifire), реализация — отдельным чейнджем.
- **BREAKING** (для classifire): SQLite-контур fetch (`classifire/fetch.py`) объявляется замороженным после переноса; новые данные собираются единым фетчером.

## Capabilities

### New Capabilities

- `fetch-metadata`: контуры получения метаданных (seed, lazy fetch, batch refresh, retry, enumeration), работа per-registry, идентичность пакета при нескольких реестрах, объём и глубина данных per версия, семантика upsert.
- `fetch-probe`: скачивание дистрибутива и извлечение офлайн-фактов (entry_points, top_level, состав файлов, bin-скрипты, README); идемпотентность, лимиты, выбор артефакта.
- `registry-access`: реестры как данные — адреса, auth, протокол коннектора, несколько реестров одной экосистемы, прокси-режим, правила отправки credentials, rate limiting.
- `fetch-reliability`: классификация ошибок, retry-политика, очередь неудач, дедупликация конкурентных загрузок, наблюдаемость.

## Impact

- **Код (целевой)**: backend PackageHub — `connectors/`, `fetcher/`, `tasks/`, новая probe-задача Celery, миграция схемы (`dist_probe`, расширение `registry.auth_config`); classifire — `fetch.py`/`config.py` замораживаются, их поведение переносится.
- **Схема БД**: новая таблица `dist_probe` (FK на `package_version` + `artifact_filename`, не FK на `artifact` — артефакты пересоздаются при sync); `registry.auth_config` начинает использоваться; новые поля `registry.protocol` и `registry.enumerate_enabled`; флаг коллизии имён на связке пакет↔реестр.
- **Внешние системы**: весь трафик к реестрам может идти через прокси-репозиторий (кеш артефактов); прокси задаётся per-registry, а не глобальным env.
- **Не затрагивается**: резолвер, каталожный API, UI, классификатор (потребитель probe, отдельный чейндж).
