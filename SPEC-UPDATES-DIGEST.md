# PackageHub — Понятный дайджест обновлений

> Страница Updates отвечает на вопрос «что изменилось в пакетах, которые мы используем, и нужно ли что-то делать», а не только перечисляет новые версии.

**Версия:** 0.1-draft
**Дата:** 2026-11-06
**Статус:** решения приняты (§9), U0 сделан, дальше U1.
**База:** [SPEC-DAILY-UPDATE.md](./SPEC-DAILY-UPDATE.md) §5. Журнал `package_events`, прогоны и API остаются; спека меняет §5.2 и дополняет ответ `/updates/summary`.

## 1. Что не так сейчас

Таблица описывает страницу до U0. Ошибки #56, #57 и #58 уже исправлены, остальное осталось.

Замеры на стенде за 2026-10-27 — 2026-11-06: 848 пакетов, 41 тыс. версий, 60 ежедневных прогонов без сбоев. Копить есть что, показывать почти нечего: из 205 событий `release_added` реальных релизов 117.

## 2. Что показываем

Читатель — аналитик, владелец сервиса: он анализирует зависимости и понимает их на уровне DevOps, но не пишет код этих пакетов. Ему важнее влияние изменения на каталог (что затронуто, что поменялось в зависимостях и лицензиях), чем подробности релиза. Страница даёт ответ сверху вниз: сначала что требует внимания, потом что обновилось, остальное скрыто.

Набросок, числа условные:

```
Updates                                [Today] [Week] [Custom]
7 of 7 sources checked, latest 10:03

NEEDS ATTENTION (2)
  python-dateutil  pypi                       3.0.0 → 4.0.0   MAJOR
    Extensions to the standard Python datetime module
    used by 9 packages · released 3 Nov · 2 dependencies added · Release notes

UPDATED (31)                  [Ecosystem ▾] [Kind ▾] [☐ Prereleases (19)]
  aws-sdk-go-v2  go           13 modules · patch · released 5 Nov          [+]
  Spring Boot  maven           9 modules · 4.1.2 → 4.2.0 · released 5 Nov  [+]
  pydantic  pypi                              2.14.2 → 2.14.3 · patch
    Data validation using Python type hints
    used by 6 packages · released 5 Nov · Release notes
```

Правила:

- **Внимание:** `unavailable`, `vulnerability_added`, `removed`, `yanked`, `deprecated`, настоящий `major`, смена лицензии, новые зависимости. Если ничего нет, одна строка: «Nothing needs attention».
- **Строка пакета:** экосистема, родное имя, описание в одну строку, `from → to`, тип изменения, «used by N», дата релиза, что изменилось, ссылка на заметки о выпуске.
- **Семейство:** пакеты одного релиза свёрнуты в строку с раскрытием (§4).
- **Пререлизы** скрыты по умолчанию, счётчик рядом с переключателем. Пререлиз в «Внимание» не попадает, если у него нет других флагов.
- **Дата** — `occurred_at`. Если её нет (17 из 19 событий Maven), дата обнаружения с пометкой `detected`.
- **Сортировка внутри раздела:** по числу зависимых пакетов, затем по дате.
- **Фильтры** экосистемы и типа живут в URL, чтобы ссылкой можно было поделиться.

## 3. Важность пакета

Скачивания есть только у crates (127 из 127), у остальных шести экосистем данных нет. Основной сигнал поэтому — `used_by`: сколько пакетов каталога зависят от этого.

- Считается по `dependencies.resolved_package_id` на лету и только для пакетов дайджеста. Новых колонок не нужно.
- Правило: число различных других пакетов, у которых **последняя версия** (`packages.latest_version`) имеет зависимость типа `runtime`, `peer` или `provided` с `resolved_package_id` = этот пакет. Пакет не считает сам себя; `dev`, `build` и `optional` не считаются (у последних версий npm 712 dev против 123 runtime — они раздули бы число); зависимость старой версии не считается; два варианта одной версии (`variant_registry_id`) и несколько зависимостей одного пакета считаются один раз. Один дополнительный запрос на ответ, сгруппированный по `resolved_package_id`.
- Покрытие проверено: у последних версий всех 848 пакетов зависимости загружены. У большинства экосистем пакетов с нулём зависимых единицы, у RPM — 104 из 218.
- Ограничение: это важность внутри нашего каталога, а не в мире. Это то, что нужно: пакет важен тем, что он используется у нас.
- `origin` показываем подсказкой: `manual` и `seed` — «tracked directly», остальное — «dependency».

## 4. Семейства

Ключ считается в слое дайджеста, контракт плагина не меняется:

| Экосистема | Ключ |
|---|---|
| Go | корень репозитория из пути модуля: `github.com/aws/aws-sdk-go-v2` |
| Maven | `groupId` |
| npm | скоуп |
| PyPI, crates, NuGet | `repository_url`, иначе `homepage_url` |
| RPM | имя пакета: `rocky-8/tzdata` и `rocky-9/tzdata` — одно семейство |

Строка сворачивается, если в окне у ключа два пакета и больше и они обнаружены в один день. Имя семейства — общий префикс или имя ключа. Если семейство содержит флаг риска, этот пакет показывается в «Внимание» отдельной строкой.

## 5. Что изменилось в релизе

Новый блок `details.changes` у `release_added`. Пишется при обнаружении, только для стабильных версий на вершине пакета:

```json
{"dependencies_added": ["urllib3"], "dependencies_removed": [], "license": {"from": "MIT", "to": "Apache-2.0"}}
```

- **Зависимости:** сравниваем набор прямых runtime-зависимостей новой версии и `previous_version`. Сейчас у новых версий зависимости часто не загружены: в npm есть у 2 из 13, в Maven у 2 из 19. Поэтому ежедневный прогон загружает их для новых стабильных версий: это порядка сотни документов в неделю.
- **Лицензия:** у версии лицензии нет, сравниваем поле пакета до и после синхронизации.
- **Старые события** не пересчитываются: `changes` отсутствует, строка показывается без этого блока.
- **Заметки о выпуске:** ссылка на `<repository_url>/releases` для GitHub и GitLab, иначе на страницу пакета в реестре. Содержимое не скачиваем.

## 7. API

`GET /updates/summary` дополняется, существующие поля не меняются:

```json
{
  "totals": {"attention": 2, "prereleases": 19},
  "sources": {"total": 7, "ok": 7, "latest_finished_at": "...", "problems": []},
  "packages": [{
    "description": "...", "origin": "dependency", "used_by": 9, "released_at": "...",
    "prerelease_only": false, "family": "github.com/aws/aws-sdk-go-v2",
    "changes": {}, "release_notes_url": "..."
  }]
}
```

Параметры: `ecosystem`, `kind` (можно несколько). Сворачивание семейств и скрытие пререлизов делает страница, чтобы API оставался полным списком.

## 9. Решения владельца

Приняты 2026-11-06:

1. **Читатель:** аналитик, владелец сервиса, понимание на уровне DevOps.
2. **Go:** описание и лицензия остаются пустыми, строка показывает репозиторий. GitHub API и `pkg.go.dev` не используем.
3. **Старые события:** пересчитаны миграцией 0014: `bump` и `previous_version` у всех `release_added`, 88 строк `torch` помечены как backfill.
4. **Пререлизы:** скрыты по умолчанию, рядом счётчик.
